# Scope

In (v1): a Claude plugin with one skill that starts and stops a local companion and instructs the agent (Claude in the chat); a Python standard-library backend on 127.0.0.1 (`--host --port --data-dir`) with the companion API; fetching hits through one service adapter (Syften for Reddit and Hacker News, the Apify LinkedIn post search, the Apify Reddit thread actor, the Hacker News Algolia API) with base URLs and tokens from the environment or `.env.local` in the data folder; dropping already-known threads (keys and aliases); loading a thread with its comment tree; summaries `{question, others, angle}` and reply drafts written by the agent and stored as runs; the deterministic lint of every draft (hard rules and posting mode); status per thread (drafted, posted with the comment link, skipped, Reopen; expired derived 14 days after the run date, the day the agent put the thread on the board; posted today out of 5 shown); feedback per thread on the board, the feedback queue the agent follows through the feedback watcher and resolves as applied or declined with a note, explaining in the chat when the new draft alone does not; lessons.md learned from feedback; config (mode expertise, light or open, handles, cursors); the runs archive; change events for the agent (the feedback watcher) and the reload offer on the board; the data folder `~/.social-engagement` (`--data-dir` or `SOCIAL_ENGAGEMENT_HOME` override it) with the data files data.json, state.json, feedback.json, lessons.md, config.json, runs/ behind one store module (JSON files); the served board (svenroth.ai tokens, Inter and Geist Mono): platform switch, status filter Open, Posted, Skipped, Expired, All, thread list newest first with j/k, one thread rendered the way its platform shows it, summary and feedback, status actions, draft card with Copy and Open thread, one comment count per thread (the stored tree) in the list and the post header, character count for X, the list as a picker and a wrapping platform switch on a phone; an optional internal review of drafts by an Opus sub-agent, run by the agent on the person's go. Only the Syften and Apify tokens are needed. Tests run against a local fake server that answers from the recorded files in `seed/recorded/`.

Later (not in v1): keyword tuning (Syften filters get/set, archive search, LinkedIn query precision and the tuning log), LinkedIn author feeds, looking for replies to the person's posted comments.

Out: posting, commenting, connecting or messaging on any platform (the person posts every reply by hand); a chat panel in the board (the chat is the Claude app); any model call from the backend; any service or key beyond Syften and Apify; reading X by script; editing drafts on the board; accounts, sign-in and remote access; deployment (the plugin is installed, not deployed); network or keys in any test.
