# Mini-Plan: defer means defer — the park lifecycle

- **Run ID:** iterate-2026-08-01-triage-defer-lifecycle
- **Spec:** `2026-08-01-triage-defer-lifecycle.md`

## Decision 1 — the park expires by DERIVATION, not by a writer

**Chosen.** `read_all_items` resolves a parked entry whose revisit date has
passed as `status: "triage"`. Nothing is written; the stored log still says
`snoozed`, and the resolved view adds `revisitAt` plus `revisitDue`.

**Alternative considered — a sweep materialises the expiry** by appending a
`status: triage` event when the date arrives. Rejected on three counts: it needs
something to run it (there is no scheduler that owns the triage store; the
nearest thing is a Stop hook, so expiry would depend on a session happening);
it writes a decision event for something nobody decided, which corrupts the one
thing the append-only log is for; and every surface stays wrong until the sweep
runs, which is exactly the "deferred is not honoured" complaint this run exists
to fix. Derivation makes all ten consumers correct simultaneously and for free.

**Consequence accepted:** `read_all_items` becomes time-dependent. Contained by
threading an explicit `now` through the pure helper (tests pin it; the store
defaults to UTC now), and by the conservative unreadable-date rule (AC-7).

## Decision 2 — the rules live in a new pure module

`shared/scripts/lib/triage_defer.py` — `REVISIT_FIELD`, `parse_revisit_date`,
`resolve_revisit`, `apply_revisit_expiry`, `suppresses_reimport`,
`AUTO_RESOLVABLE_STATUSES`, `is_auto_resolvable`, `DEFERRED_TOP_N`. No I/O, no
lock, no git. `triage.py` reaches it through the existing lazy
`load_shared_lib` path (ADR-045: no eager `lib` import at `triage.py` top).

**Alternative — put it in `triage.py`.** Rejected twice over: the file is at 837
LOC under ADR-100 and this would push it further with logic that has no reason
to sit behind the lock, and the rules are pure functions that deserve direct
unit tests rather than tests that must construct a store first.

## Decision 3 — `list --json` becomes a versioned envelope

```json
{ "contractVersion": 2, "open": [ … ], "deferred": [ … ] }
```

**Alternative — keep the bare array and let parked entries into it** with their
status attached. Rejected: the array is contractually *open items only*, so
every existing consumer would render parked entries as open — strictly worse
than today's invisibility. And decision #3 says "in their own section"; a flat
array has no sections. The operator already accepted the cost of a version bump
plus a consumer change in the Command Center repository.

**Blast radius, measured, not assumed:** the Command Center does **not** shell
out to this CLI at runtime — it has its own TypeScript reader and pins the
contract with a committed fixture (`triage-union-cli-list.json`) regenerated by
hand. So nothing breaks live; what breaks is the parity gate the next time
someone regenerates. That is why AC-13 files a card instead of pretending the
change is self-contained.

## Decision 4 — one declared answer for "which statuses may a producer close"

`AUTO_RESOLVABLE_STATUSES = ("triage", "snoozed")`. Each widened site swaps its
literal `status != "triage"` read filter and its `expected_status="triage"`
write precondition for the shared name — line-neutral edits. `mark_status`
already accepts a tuple of expected statuses; that is exactly what S2 built.

**The audited inventory** (an external reviewer was right that "seven" was
ambiguous — here it is exactly, each verified by reading the code):

| # | Module | Function | Widened? |
|---|---|---|---|
| 1 | `shared/scripts/github_triage/resolve.py` | `resolve_stale` → `_dismiss_if_open` | yes |
| 2 | `shared/scripts/github_triage/resolve.py` | `resolve_pr_ci` → `_dismiss_if_open` | yes |
| 3 | `shared/scripts/hooks/check_drift.py` | resolve pass | yes |
| 4 | `shared/scripts/lib/phase_quality/_triage_bundle.py` | `_dismiss` | yes |
| 5 | `plugins/shipwright-compliance/scripts/audit/triage_bundle.py` | `_dismiss` | yes |
| 6 | `plugins/shipwright-compliance/scripts/lib/sbom_generator.py` | `emit_undeclared_triage` | yes |
| 7 | `plugins/shipwright-compliance/scripts/lib/test_evidence.py` | `emit_test_failure_triage` | yes |
| — | `shared/scripts/github_triage/resolve.py` | `migrate_legacy_items` → **same helper** | **no** — passes `("triage",)` |
| — | `shared/scripts/tools/accepted_risks_converge.py` | `_apply_triage` | **no** — operator convergence |
| — | `shared/scripts/tools/triage_promote.py` | `promote` / `dismiss` | **no** — operator decisions |

Seven producer paths across six modules. The `migrate_legacy_items` row is why
`_dismiss_if_open` takes the expected set as a **parameter** instead of being
widened in place: three callers share it and one must not move.

**This table was false when first written, and the Stage-1 spec review caught
it.** Row 7 (`test_evidence`) had its *precondition* widened but not its *read
filter*, so that producer dropped every parked entry before reaching the write
— it had taken on AC-9a's cost while delivering none of AC-8's benefit. The
table is left standing with this note rather than quietly corrected, because
the interesting fact is not the typo: it is that a table asserting "widened:
yes" seven times was believed, and that only a test PER PATH could disprove it.
That is now AC-26, and `test_the_test_evidence_producer_closes_a_parked_entry`
reproduces the defect exactly (`dismissed == 0`) when the fix is reverted.

## Decision 5 — the bloat cost is paid deliberately, not smuggled

`shared/scripts/triage.py` (837, ADR-100) and
`shared/scripts/tools/triage_promote.py` (324, grandfathered) both grow. The
gate's remediation 3 — bloat-exception ADR plus a deliberate `current` bump in
the same commit — is the sanctioned path and the one ADR-100 already used for
this file (592 → 719 → 837). Splitting `triage.py` is refused for the reason
ADR-100 gives: the lock, the path helpers, the append writer and the union
reader share invariants that only hold when they are read and modified
together. Growth is held down by Decision 2 (all new rules land in the new
module); the delta is the wiring only.

## External plan review — round 2 (`revise`), and what it changed

Round 2 answered on the revised plan: `openai` `revise` with 8 findings,
`gemini` truncated again (`unavailable`). The findings moved from design gaps to
implementation precision — all accepted.

| # | Sev | Finding | Disposition |
|---|---|---|---|

| 3 | medium | `unpark`'s reason was neither required nor specified. | **AC-14** names the interface and requires the reason under the same validation as `dismiss`/`defer`. |
| 4 | medium | "Seven" resolver sites was ambiguous; missing one recreates the defect for that producer. | Exact audited table above. Also caught a real trap the count was hiding: `_dismiss_if_open` is shared by **three** callers, one of which must not widen. |
| 5 | medium | Permissive date parsing would let the stored classification diverge from the CLI's promise. | **AC-21**: strict exact-form `YYYY-MM-DD`, real calendar date; aware UTC clock read once at the store boundary. |
