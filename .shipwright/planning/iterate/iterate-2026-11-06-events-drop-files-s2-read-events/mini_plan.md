# Mini-plan S2 (events-drop-files): the read_events contract
Goal: ONE assembling reader (new lib/events_read.py): legacy file in FILE order, then archive and drop files merged by (parsed instant, id); per-file status (ok/corrupt/empty/unreadable) with split_records recovery; archive/drop duplicate rule (same id+content collapses, different content kept and flagged); absence-gate primitive (a non-ok DROP file of the run's key blocks, legacy/archive tolerant). events_log gains event_files() and latest_event_dt/finalized_run_ids read drops+archive. Position readers (last grade snapshot, handoff last iterate and Last Events, dashboard test status and Recent Changes) use newest-by-ts, not list position. Replay-gate known set tightened by the S2 items.
Files: shared/scripts/lib/events_read.py (new), events_log.py (net -2 lines, stays <= 300), events_layout.py (reader moved out), config.py, event_dedup.py, tools/generate_session_handoff.py, update_build_dashboard.py, record_event.py (1 line: skipped_files counts like corrupt), shared/tests/test_events_read.py, compliance test helper (layout-agnostic read), events_replay_known_failing.json.
Tests: order, status, recovery, dup rule, KC8 (exact key, legacy/archive/other-run tolerated), position readers, KC1 byte-identical renders on the unsplit/split fixture pair (handoff, dashboard, throughput) plus read_events/latest_event_dt/finalized_run_ids equality; replay gate tighten.
Risks: ADR-045 load contexts (events_log keeps its single by-path sibling; new module is package-only); legacy behaviour for out-of-order legacy logs changes only in the "newest" pickers (intended); renderers on their own read paths (compliance twin, campaign status, verifiers) belong to S3/S4.
Alternative approach considered: none beyond the brief.
