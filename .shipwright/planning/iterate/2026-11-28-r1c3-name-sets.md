# Iterate Spec: r1c3-name-sets

- **Run ID:** iterate-2026-11-28-r1c3-name-sets
- **Type:** change
- **Complexity:** medium. The change touches about 60 files across 8 plugins and `shared/`, the resolver, the sensitive-path regex and the skip-review set of the required PR-review gate, and the churn/derived-snapshot machinery (cross_component).
- **Status:** implemented

## Goal
This is the fifth R1 PR of the root-files campaign (BRIEF `.shipwright/planning/campaigns/2026-11-14-root-files-into-shipwright-dir-BRIEF.md`, item 12.12 (a)). After R1c-2 every reader and writer finds a moving file through `path()`. What still RECOGNISED a moving file by its root name were path sets, allowlists, regexes, a git pathspec, phase hints and messages. After R3 a file at `.shipwright/config/<name>` would have been missed by them: a `test_results` copy would not count as a derived snapshot, and a risk register there would fall outside the sensitive-path regex. This PR makes each recogniser see both places. It ends the safety window of 12.12 (b).

## Design
1. **The resolver's sets cover both places.** `snapshot_paths()` and `run_written_paths()` now return the new AND the legacy path, as their docstring already promised. `DERIVED_SNAPSHOTS` and `RESTORABLE_SNAPSHOTS` follow, so the ledger in either place is never staged and never reset.
2. **Hand-written sets use `known_rels(key)`.** This covers `churn_merge.CHURN_ALLOWLIST` (new `TEST_RESULTS_RELS`), the `resolve_churn_conflicts` "ours" side, `compliance_refresh` classification and exclusions, `change_type_paths`, `review_diff_threshold.UNCOUNTED_FILES`, `section_file_list.FRAMEWORK_BOOKKEEPING`, `compliance_input_state.PRODUCER_STATE`, the design and plan boundary prefixes, `artifact_migrations.ALLOWLIST` and `review_record_tier.SENSITIVE_PATH_RE` (it only gains sensitive paths). **`pr_review_skip_safety` stays at the root place on purpose.** Skip-safety LOOSENS the required review gate, so it follows the file and never runs ahead of it. Otherwise, in an unmigrated repo, a PR adding the ledger at the new place would skip review. R3 switches it together with the move (internal architecture review). `project_root.CONFIG_MARKERS` uses `all_known_rels(marker=True)`, so a moved project is recognised without the root stub. `change_type_paths` judges a moving root file at its new place exactly as at the root (`_AS_ROOT`). Without that, the new place would fall under the blanket `.shipwright/**` bookkeeping that every no-FR label covers, and a `docs` iterate could edit a moved baseline or risk register (internal plan review).
3. **Readers that name a place get the resolved one.** The phase-context hints hold registry keys and resolve them per project (`_where`). The fold stages `sync_config` where it lives (`_stage_paths(result, root)`). The handoff lists each config where it is. The adopt `written:` line and the nested-project marker report the real path.
4. **Labels use `name()`.** 47 module constants that only label a file in messages, argparse help or origin strings are now bound to `_sp.name(key)`. `CONFIG_FILES` in `lib.config` and `collectors._common` is derived from `CONFIG_KEYS`, so the two maps cannot drift.
5. **What stays.** The event log does not move: `EVENT_FILE`, `EVENTS_LOG`, `EVENT_LOG_NAME`, `UNION_PATHS` and the event-log entries of the sets keep `rel("events")`, which the event-log reference guard tracks. `churn_merge.TEST_RESULTS` keeps the legacy name that tests write; sets use `TEST_RESULTS_RELS`. Adopt's dry-run preview keeps `rel()`, because it names the file adopt would create, and creation stays at the root until R3.
6. **Guards.** The new test `test_shipwright_paths_recognisers.py` drives each recogniser with a path in the new place. Its AST net forbids `_sp.rel`/`_sp.legacy_rel` of a moving key in production code outside the resolver, adopt's dry-run preview and two kept constants (`churn_merge.TEST_RESULTS`, the skip-safety root entry). A positive control is included. The constants inventory goes from 73 to 16 entries. They are the constants and sets that hold the event log, plus the two kept root spellings of `test_results`. Two halves of the tests pin today's behaviour rather than fail on the old tree: the review-size half of AC2 (the `.shipwright/` prefix already uncounts the path) and AC5 (skip-safety stays as it is). The R1c-1 pin keeps its first half ("no production file names the folder"). Its second half now forbids only `new_rel()`, the new place on its own that a writer would use. Recognising a file there is reading, not creating it.

## Acceptance Criteria
- [x] AC1: The run-written ledger counts as a derived snapshot in either place. It is never staged or restored, it sits in the churn allowlist, and it is classified `run_written`.
- [x] AC2: Finalization records in the new place do not count toward the review-size threshold or section attribution, while real code still counts.
- [x] AC3: A directory whose run config is only in `.shipwright/config/` is a Shipwright project.
- [x] AC4: A risk register or bloat baseline in the new place is a sensitive path for the PR-review tier. The match stays anchored: a basename elsewhere does not count.
- [x] AC5: The ledger is skip-safe only where it lives today, at the root. Its new place still needs a review, and a planted basename borrows nothing.
- [x] AC6: A no-FR label covers a moved root file exactly as it covers the root file. The compliance producer snapshots and reports the config where it lives. The fold stages `sync_config` where it lives. The phase context points a skill at the moved file.
- [x] AC7: No production code spells a moving file by its root name (AST net with a positive control). The inventory only shrinks, from 73 to 16, and the unmigrated repo behaves as before (full F0 suite).

## Spec Impact
NONE. Nothing creates the new places yet, so every set contains the same root names as before plus paths that do not exist. The only observable difference in an unmigrated repo is that the derived and churn sets each hold one more entry, the new place of `shipwright_test_results.json`, which matches no file.
