# Campaign brief: per-run event files (`events-drop-files`)

Date: 2026-11-04 · Status: DRAFT v2 (after Opus plan review: revise, 10 blockers folded in) · Source: issue #978 (parallel iterate PRs show CONFLICTING on GitHub because `merge=union` is local-only). Full design: `2026-11-04-events-drop-files-DESIGN.md` in this folder (its section 10 overrides older sections on conflict; its section 8 holds kill criteria KC1-KC8, cited below).

## 0. Goal
Two iterate PRs that run in parallel never conflict on GitHub because of the event log. Today every run appends to the one tracked `shipwright_events.jsonl`; `.gitattributes merge=union` only helps locally, GitHub's mergeability check ignores it. Each run instead writes its own file, so two PRs only ever ADD different files. Everything that reads events keeps seeing one ordered log.

## 1. Evidence (throwaway spike, never merged)
- Legacy layout: `git merge-tree` WITHOUT union conflicts on 3 of 3 pairs. Drops layout: clean on 3 of 3. After two squash merges a real `ensure_current` on the third branch integrates and sees all drops, once the classifier and `_reconcile_events` are migrated.
- F11 `_event_committed_in_head` returns False for a correctly committed drop (every run would fail until migrated). The `.lock` file must live outside the folder.
- 3075 event-related shared tests pass on legacy; with the drops layout 53 fail in 18 files (a lower bound: plugin test roots and integration tests were not measured).

## 2. Principles
- Readers strictly before writers. The default layout stays legacy until S9a. Nothing before S9a changes what a consumer's iterate writes, with ONE exception that is decided, not hidden: bullets (S5) go live without the flag because old consumers cannot see them by construction (design 4.3); S5 therefore ships behind its own release note and the bullet writer is gated on the S2 reader being released.
- Every unit has a "Done when", its own kill criteria, a guard test and the full review cascade. A red item stops the campaign for the operator.
- `events_layout` in `shipwright_sync_config.json` is never removed from an existing repo ("absent = legacy" forever).
- The env var `SHIPWRIGHT_EVENTS_LAYOUT` is a TEST-ONLY override: it is honoured only when `SHIPWRIGHT_EVENTS_LAYOUT_TEST=1` is also set (set by the test harness and by this repo's own `ci.yml` replay step; never by plugins or consumer CI templates in `shared/templates`). Precedence otherwise: config key, then default legacy. S0 also owns reading the `events_layout` config key at runtime. Subprocess tests inherit the var on purpose.
- Format changes are DROPS-ONLY. The stamped `run` field, 16-hex ids and `event_amended` apply only under the drops layout; under legacy the bytes written stay exactly as today (old `dedup_event_lines` compares exact lines; old readers do not know `event_amended`). Any other change visible under legacy (e.g. S4 running `ensure_current` before the F11 committed-check) must be a no-op for legacy and says so in its test. S6's integrity check and S7's sentinel are no-ops while no drops exist.
- Sonnet builds, Opus reviews. Plugin-side merges are followed by the plugin cache sync.
- Docs owed per unit: `docs/hooks-and-pipeline.md` artifact-write matrix (S4, S5) and `docs/guide.md` (S5, S9a).

## 3. Units
Each "Done when" cites the design's kill criteria.

- **S0 Harness and dormant writer.** Land the drops path in `events_log` as a DORMANT code path (test-only override above), the bare-origin integration harness (legacy baseline vs drops, real `record_event`/`ensure_current`, `merge-tree` without union), and the standing replay gate: every event-related test root (`shared/tests`, `shared/scripts/tests`, `shared/scripts/tools/tests`, each `plugins/*/tests`, `integration-tests`, one root per process) runs under the test-only override. The gate is a RATCHET: it records the known-failing set and may only shrink. S0 also produces the unsplit/split fixture pair (same log, split by a content-only splitter) that S1 and S2 use. Done when: legacy 3/3 conflict, drops 3/3 clean under `merge-tree` (a real `ensure_current` on drops is NOT an S0 pass condition; it works only after S3); the gate runs in this repo's CI with a stated time budget; gate lists the known set (S2/S3 product-reader items vs S4 writer/finalization items, split by unit); setting the plain env var without the test flag changes nothing.
- **S1 WebUI reader (part 1).** Own repo: reads legacy plus drops, assembled order, per-file status. Done when: KC1 for the WebUI node script (campaign status byte-identical on the unsplit vs split log). The minimum WebUI version is NOT recorded here (see S5b).
- **S2 `read_events` contract.** One assembling reader (legacy in file order, then archive and drops by parsed instant then id), per-file status, `split_records` recovery, position-reader fixes, absence gates fail on a non-ok DROP file of the run's key (legacy and archive stay tolerant). Done when: KC1 (every renderer byte-identical on the unsplit baseline vs the split log), KC8, replay tests green, gate ratchet shrinks by the S2 items.
- **S3 Readers, aliases, classifiers, guards.** Migrate every reader: `EVENT_FILE`, `EVENTS_LOG`, `EVENT_LOG_NAME`, `resolve_events_path`; `_reconcile_events`; `regenerate_campaign_statuses`; `compliance_input_state`; `event_context_index` fingerprint; `gitattributes_union`; plan/design phase gates; the change-type classifier; and the named plugin readers: compliance (`audit/group_b.py`, `group_d.py`, `_group_d_promise.py`, `audit/_events_read.py`, `collectors/change_history.py`), grade (`lib/routing.py`, `authoritative.py`), test `boundary_coverage_report.py`, iterate `campaign_progress.py`, adopt `validate_adoption.py`, and the classifiers `review_diff_threshold`, `section_file_list`, `churn_merge`, `project_root`, `gitignore_selfheal`, `worktree_isolation`, security `pr_review_generated`/`pr_review_skip_safety`. Classifiers list all three folders (`.d`, `.archive`, `.quarantine`). Reference-based guard over code, prompts, templates, docs. Done when: KC2 (no unclassified occurrence), the read-side items of the gate ratchet are gone, real `ensure_current` on a behind-main branch carrying its own drop plus campaign-status regeneration pass in the integration test.
- **S4 Writers and finalization.** One writer module (`record_event` plus the duplicate `EVENT_FILE` users and `verifiers/common.read_events_jsonl`; adopt event seeder, `append_phase_history`, `append_iterate_entry`, `convert_configs_to_events`, `write_decision_drop`), one live key-precedence function (the S2 replay splitter keeps its own content-only rule, design 10.2), `run` field stamped (drops only), 16-hex ids with same-id dedup rule, name validation (cap 80), dedup scope per design 10.2, lock outside the folder, rotate-on-commit with the `ls-tree`/HEAD-marker probe (never `git status`); F6 staging by own key; F5b; F11 committed-check with `ensure_current` run BEFORE it; F7b seal; `ensure_current` ABSORB step; `attach_commit_to_event` as `event_amended`; `validate_event_log`, `commit_event_followup`, `integrate_main`/`integrate_merge` validating drops from a merge; `dedup_event_lines` and `event_context_index` ignoring the `run` field in byte comparison; prompts/docs. Writers stay dormant (default legacy). Done when: KC4 (12 parallel Stop-hook writers, no duplicate `phase_completed`; a re-run of `plan` with a fresh run id must not duplicate), "F6 forgets to stage, F11 FAILS" after the absorb, the write-side items of the gate ratchet are gone (ratchet empty).
- **S5 Bullets, and S5b WebUI part 2.** Bullets as `.md` in `.shipwright/agent_docs/decision-drops/bullets/`, fold at release (bullets before ADRs), context-load cap 20 plus "N more pending", budget/shape/architecture checks read folded plus pending, `prompt_injection_scan` on bullet files; S5 reaches consumers no earlier than the S5b WebUI release (otherwise WebUI users would not see pending conventions/architecture updates until the next fold); the `check_conventions_reviewed` mtime adaptation is part of S5. S5b (WebUI repo): full contract (amendments, bullets folded plus pending, per-file status, duplicate-id rule, `ls-tree` + `cat-file --batch` reader); records the minimum WebUI version. Done when: KC7 (two branches adding bullets are clean under `merge-tree`; an old-plugin changelog run leaves bullets untouched; render identical pending vs folded; cap overflow warns; an old-plugin `aggregate_decisions` and an old WebUI against bullet drops show no bullet as an ADR).
- **S6 Fold and integrity.** Fold tool, quarantine (only files with zero recoverable records AND non-ok at the merge-base, re-checked by the CI checker), emergency fold, full fold, key/path validation, CI integrity check (a PR may only ADD files under the folders; fold and quarantine exceptions byte-identical). Done when: KC6 (modify/delete of a file existing at the merge-base, path-traversal key and forged-run-id append all blocked; fold racing an open PR clean).
- **S7 Mixed versions.** Layout sentinel (post-change plugins fail closed on unknown layouts), release-evidence producers refuse unknown layouts, consumer CI check judged at the merge-base; `init`/`adopt` write `events_layout` explicitly; guard that refuses writing legacy when a drops folder exists; conditional gitignore self-heal and the tracked-ness probe with a sample path. Done when: mixed-version cases of KC3 pass (old writer + new reader, new plugin on unknown layout fails closed, release evidence refused).
- **S8 Full integration.** Whole-system test of design section 8 item 3, microbenchmark (run-scoped read <= 20 ms; whole log <= 0.3 s at 300 files; Windows and Linux CI), both rollbacks rehearsed on a copy of real history. Done when: KC3 and KC5 green; this is the gate for S9a.
- **S9a Flip, dogfood.** Preconditions: S8 green; a plugin release with S2-S7; a WebUI release with S1+S5b in use (operator). This repo sets `events_layout: drops` and runs two weeks (operator-timed wait). Announce the flip to the team and note that a plugin from before S2 running F11 on a drops repo fails loudly. Done when (operator decides go/no-go): zero event-log conflicts on parallel PRs, zero F11 or absence-gate false failures, empty quarantine list, benchmark budgets hold on real data.
- **S9b Reporter pilot.** Consumer CI check ON by default (reporter and operator involved). Done when (operator and reporter decide): the reporter's parallel PRs show no event-log CONFLICTING over an agreed window and no false gate failures.
- **S9c Stop branching on the flag.** Gated on: sentinel present in every supported plugin line AND minimum WebUI version (S5b) in use, not on the calendar. If the gate is not met nothing breaks; a warning plus a tracked issue appears. The key is never removed.

## 4. Not in this campaign
`triage.jsonl` (reporter data: 0 of 7 PRs touched it); the stopgap of ensure_current-only mitigation (pending answer on #978); stopping to track the event log; rewriting history of existing events.

## 5. Risks
- An old READER on a repo that already has drops is the one unmitigated case: gates see a run as missing, derived renders miss runs and self-heal on the next new-plugin iterate. Bounded, exists only between the flip and the last teammate updating.
- Plugins released between S3 and S7 read drops without failing closed (the sentinel lands in S7). Harmless while no writer is live (default legacy until S9a).
- Core design stable since review round 3; later findings were code touch-points, which the spike confirmed and S2-S4 close. Details are decided in the iterates.
