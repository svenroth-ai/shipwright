# F6 — Commit (Conventional Commits)

- **Feature:** `feat({scope}): {description}`
- **Change:** `refactor({scope}): {description}` or `feat` if user-facing
- **Bug:** `fix({scope}): {description}`

By this point F3, F3a, F4, F5, F5a, F5b, and F5c have all written
their artifacts into the working tree. Stage everything explicitly
rather than using `git add -A` (avoids accidentally picking up
unrelated dirty files):

```bash
# Code + tests (run-specific paths)
git add <source files edited in build>
git add <test files added/modified in build>

# Finalization artifacts (always)
git add {project_root}/CHANGELOG-unreleased.d/       # F4 drop files (one or more)
git add {project_root}/.shipwright/agent_docs/decision-drops/{run_id}_*.json   # F3 decision-drop(s), if this run wrote one — tracked since iterate-2026-08-08-track-decision-drops; ships in THIS run's own PR (skip only if the project gitignores the directory). Glob-scoped to THIS run_id, NOT the whole directory — see note below.
git add {project_root}/.shipwright/agent_docs/iterates/          # F5c summary + immutable <run_id>.test-results.json + any migration quarantine
git add {project_root}/shipwright_run_config.json
git add {project_root}/shipwright_events.jsonl       # F5b work_completed event — per-tree, MUST ship in the PR (skip only if gitignored in this project)
git add {project_root}/.shipwright/triage.jsonl      # tracked triage backlog — producers append during the iterate; deltas ship in the PR (skip only if gitignored in this project)

# Conditional finalization artifacts
git add {project_root}/.shipwright/agent_docs/conventions.md       # if F3a wrote learnings
git add {project_root}/.shipwright/agent_docs/architecture.md      # if F2 flagged structural impact
git add {project_root}/.shipwright/planning/**/spec.md             # if F1 flagged drift
git add {project_root}/.shipwright/planning/iterate/*.md           # if medium+ (iterate spec / mini-plan)
git add {project_root}/.shipwright/planning/iterate/<run_id>/      # review record (reviews.json) + ci_supplychain_ack.json + architecture_brief.md (Step 3.5's second call) + risk_recheck.json (campaign sub-iterates only) — the *.md glob above does NOT match them
git add {project_root}/.shipwright/planning/adr/                   # whenever it is dirty — NOT only when F3 wrote an ADR. F3 refreshes INDEX.md on every drop, so a run that wrote no ADR can still have repaired a stale index; leaving that unstaged makes the LOCAL drift guard pass against a repaired worktree while CI fails against the committed tree. A folder-level add is a no-op when nothing changed. Stages the <run_id_sanitized>-<slug>.md AND its INDEX.md row together — both or neither.
git add {project_root}/.shipwright/planning/iterate/campaigns/<slug>/status.json  # if a campaign sub-iterate (F5b Step 6 re-projected the per-tree board — campaign S3)

# NOTE: the DERIVED SNAPSHOTS are deliberately absent — `.shipwright/compliance/`,
# the three `.shipwright/agent_docs` snapshot MDs, and
# `shipwright_test_results.json`. See the note below.

git commit -m "<type>(<scope>): <description>

<body>

Run-ID: {run_id}
Co-Authored-By: Claude <noreply@anthropic.com>"
```

If a path in the list above doesn't exist in the current project, skip
that `git add` — it just means that particular artifact wasn't touched
by this run. Never add `-A` to bypass the list.

> **The DERIVED SNAPSHOTS never enter an iterate commit**
> (iterate-2026-07-27-derived-snapshots-off-branch) — the five compliance MDs,
> `ci-security.json`, `test-traceability.json`, the three agent-doc MDs, and
> `shipwright_test_results.json`. They are still regenerated locally during the
> run (F5a/F5b), so everything that reads them still works; they simply leave the
> PR diff, and `restore_derived_to_head` puts them back so the worktree stays
> clean — ten of them. `shipwright_test_results.json` is CARRIED across the
> integration instead (`lib/run_written_ledger.py`, trg-ad29a709), because the run
> WRITES that one and no producer can put its content back. Two reasons for the
> exclusion itself. **They collide:** every iterate rewrites the same eleven
> shared paths regardless of what it changed, so N parallel iterates conflict
> N(N-1)/2 times — measured 2026-07-27, three DIRTY PRs with ZERO conflicting
> source files. **They are wrong:** a snapshot derived inside a worktree reads the
> *branch's* git history (pre-squash SHAs) and an event log missing every
> concurrently-merging branch — main's committed `change-history.md` over-counted
> commits by 11 and cited a SHA `git merge-base --is-ancestor` proves was never on
> main. The truth they derive from — `shipwright_events.jsonl` and
> `.shipwright/triage.jsonl` — DOES ship, so the view is reproducible from main
> and belongs there. Registry + rationale: `shared/scripts/lib/derived_snapshots.py`.

> **The run-specific test-results sibling is NOT the mutable derived snapshot.**
> F5c validates its embedded run id, makes the filename collision-free, and
> installs the exact bytes immutably. The directory-level add above must carry
> it with the summary; F11 fails when it exists only in the worktree. Continue
> to exclude the root `shipwright_test_results.json`.

> **`shipwright_events.jsonl` is mandatory when tracked.** Since
> iterate-2026-05-29-events-jsonl-worktree-commit the event log is a per-tree
> artifact: F5b records the `work_completed` event into **this worktree's**
> copy, and staging it here is what carries the event into the PR (and to
> `main` on merge). Skipping it strands the event outside the PR — exactly the
> bug that fix closed. The F11 verifier (`check_events_has_commit`) fails if a
> tracked log's event is not in the commit. Only skip the `git add` when the
> project **gitignores** `shipwright_events.jsonl`.

> **`.shipwright/agent_docs/decision-drops/` is the same per-tree pattern**
> (iterate-2026-08-08-track-decision-drops): the directory is now tracked, and
> `write_decision_drop.py` writes F3's drop into **this worktree's** copy — no
> more redirect to the main repo. Staging it here is what carries the drop
> into the PR; skip it and the drop is only local working-tree state. **An
> unstaged drop does not survive `git worktree remove`** — unlike the
> pre-2026-08-08 main-root redirect, which existed precisely so a gitignored
> drop would; durability now comes from this `git add`, not from where the
> file physically sits. Skip the `git add` only if the project gitignores the
> directory.
>
> **Glob-scoped to `{run_id}_*.json`, unlike every other directory-level add
> above** (doubt-reviewer MEDIUM #4). The other directory-level adds are safe
> because each is already run-scoped by directory structure (e.g.
> `.shipwright/planning/iterate/<run_id>/`); `decision-drops/` is a single FLAT directory
> shared by every run that has ever touched this worktree. A campaign's
> sub-iterates branch-hop inside ONE shared worktree (F5's own docstring), so
> a bare directory-level `git add -A`-equivalent here would sweep a leftover,
> never-committed drop from an unrelated earlier or aborted sub-iterate into
> THIS run's commit — misattributing that ADR's origin in the PR. The
> filenames are `write_decision_drop.py`'s own
> `{sanitize_run_id_for_filename(run_id)}_{NNN}.json` pattern; for the run_id
> forms this pipeline actually produces the raw `run_id` glob above matches
> them directly (sanitization only rewrites path separators / control chars /
> dots, none of which a well-formed `iterate-YYYY-MM-DD-slug` contains) — if
> in doubt, `ls` the directory for this run's actual filenames first. The glob
> naturally excludes the gitignored `INDEX.md` and its `*.tmp` siblings, which
> don't match `{run_id}_*.json` anyway.

> **`.shipwright/planning/iterate/<run_id>/reviews.json` is the same**
> (iterate-2026-07-21-review-record): the review record is written into the
> worktree during the run, and the `*.md` glob above does NOT match it. A record
> left unstaged is deleted with the worktree after the PR merges, so the Mission
> view renders an empty Review row — the precise "nobody wrote it down" outcome
> the record exists to abolish. The F11 verifier (`check_review_record`) fails
> when the record is tracked but absent from the commit, mirroring
> `check_events_has_commit`. The run-scoped `external_*review_state.json`
> markers alongside it ARE gitignored by design and correctly stay out.

> **`ci_supplychain_ack.json` shares that directory and that reasoning**
> (iterate-2026-07-28-ci-ack-per-run-home). Written by
> `record_ci_supplychain_ack.py` when the diff touches the CI trust boundary, it
> is the durable record `check_ci_supplychain_ack` reads back out of the commit.
> **Keep the add DIRECTORY-level.** Narrowing this line to `reviews.json` would
> strand the ack outside the PR, and the gate would then fail for a reason the
> author cannot see in their own working tree. The ack used to live in
> `iterate_latest` inside `shipwright_test_results.json`, which made it
> unshippable: that file is a derived snapshot, so committing it tripped
> `check_no_derived_snapshots_committed` while omitting it starved the ack gate —
> two ERROR checks that could not both be satisfied — and `restore_derived_to_head`
> reverted the ack outright during finalization.

> **`risk_recheck.json` shares that directory too, campaign sub-iterates only**
> (iterate-2026-08-05-risk-recheck-recording-integrity). Written by
> `diff_risk_recheck.py`'s Step 3.4 before the review gates, it is the durable
> record `check_risk_recheck_recorded` reads back to confirm F5c recorded the
> computed `effective_complexity`, not Step 2's stale estimate. Standalone
> iterates never run Step 3.4, so this file is simply absent for them — the
> gate SKIPs rather than fails on its absence.

> **`.shipwright/triage.jsonl` is the same** (tracked since campaign
> 2026-06-05-track-triage-jsonl): pipeline producers append findings to the

> gitignores `triage.jsonl`.

> **Campaign `status.json` is the same per-tree pattern** (campaign
