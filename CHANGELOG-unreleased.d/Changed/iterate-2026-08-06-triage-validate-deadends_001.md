The triage log validator is stricter about two shapes it used to accept in silence, and more tolerant of one it used to reject. A line holding two records glued together (from an interrupted write) is now recovered instead of failing the whole log — matching what the reader has always done. A bare value that is not a triage record, and an id that is not text, are now reported; run `shared/scripts/tools/triage_repair.py` to clean those up. Only text ids identify an item now, on both event kinds, which also fixes a crash on a malformed id and unblocks logs that could previously never be merged again.
