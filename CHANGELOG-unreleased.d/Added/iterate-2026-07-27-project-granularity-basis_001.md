Requirements now have a stated size rule. `shared/fr-authoring.md` §3a: a capability that cannot be given acceptance criteria a single delivery would satisfy is too broad and gets divided — being unable to enumerate what would settle it is the signal that it names several capabilities at once. This is a different question from how big a planning split should be, and both docs now say so. A new advisory compliance check (Group I `I6`) reports any requirement carrying no acceptance criteria at all, reading the acceptance-criteria shapes `/shipwright-project` and `/shipwright-adopt` actually emit. It never fails a build: whether a requirement is too broad is a judgement a person makes, and zero criteria is only the signal that the judgement is owed.
