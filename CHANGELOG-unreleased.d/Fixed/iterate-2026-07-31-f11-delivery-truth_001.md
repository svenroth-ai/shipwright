**An iterate now gets its pull request merged even where GitHub cannot merge it for you.** On a repository whose main branch has no protection — which includes every private repo on the free plan — GitHub refuses to set up automatic merging at all, so previously every single iterate ended with an open, green, unmerged PR after half an hour of waiting for a merger that could not exist. Finalization now asks what the code host can actually do: it still asks GitHub to merge when GitHub can, and where GitHub structurally cannot it waits for every check that exists to pass, brings the branch up to date, re-checks it, and merges the change itself pinned to the exact commit it verified. The report always names who merged it and how many checks passed, so a delivery resting only on the tests run on your own machine can never read as one the code host confirmed. Set `SHIPWRIGHT_ITERATE_SELF_MERGE=0` if you would rather nothing was ever merged on your behalf; a protected branch whose "Allow auto-merge" setting is merely switched off is reported rather than merged, and points you at that setting.
