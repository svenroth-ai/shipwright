dev_server resolves its `shared/scripts` path once at import using `os.path` instead of lazily with `pathlib`, so a test that fakes `os.name` can no longer make the executable-resolution proxy raise `NotImplementedError`. This is the deterministic defect behind the `f0-race:shared/tests` card — it looked intermittent only because the failure needed a process where nothing had already called the proxy, which pytest-xdist decides per worker.
