**changelog:** `update_changelog` no longer destroys the file it was asked to extend. It now splices the new release note into the existing document instead of rebuilding it from a fresh header, so a hand-written history — the normal case for a repo onboarded with its own CHANGELOG — keeps its title and every previous entry. Pending `[Unreleased]` bullets are preserved too (a second, unreported loss found while probing). Closes trg-6690d175 (critical); FR-01.09.
