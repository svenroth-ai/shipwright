The CI supply-chain acknowledgement gate no longer passes when git itself fails. It used to read any non-zero result from git as "this is not a git repository" and stand down quietly, so a broken git binary, a permission or ownership refusal, or a stalled repository could wave a change past the one check whose job is to make CI trust-boundary edits impossible to skip. It now stands down only when it can confirm there is genuinely no repository, and stops with an explanation otherwise.
